# 工作流与修订

## 执行顺序

1. 沿用已确认剧情和参数，明确当前要新建、续集还是局部修订；不重复索取已给信息。
2. 一致性圣经只记稳定事实；角色、场景、声音编号与别名固定。
3. 素材先复用，人物纯白底合图、场景无人单幅全景/俯视全景、道具纯白底单件静物。场景/道具不套人物合图、不带手或旁置照片；提交前核对净化后的图像锁、实际genPrompt及参考附件。只补现有参考不能约束的必要信息，不自动把生成分镜、尾帧或伴音增为素材。
4. 先画整场因果与观看节点，逐镜安排动作、发声和空间；内容占时决定长度，再划生成段并主动判断连续镜头接力。填写状态时间线、逐镜表、节拍、起止状态与切点理由。
5. 按分镜装配六字段，每段可独立提交；当前状态明确，无跨段文字记忆假设。全程无画面文字，正向约束不漏。
6. 导出共用素材库与本集分镜，核对真实接力开关、首帧、参考预算和净语速，修复错误再导入。导出流程见 [director-json.md](director-json.md)。

五份Markdown职责固定，不额外铺长篇规格、历史案例和同义自检表。阶段已有用户确认直接推进；局部修订不重做整部。

## 时间与完整性

节拍用本段成片秒数，时间范围按事件真实占时写，允许并行；合并后应覆盖全段。脚本未覆盖时间>0.4秒警告、>0.8秒报错只是机械检查，表格填满不等于内容足够。每拍核对它增加的信息、一次性结果及净占时。长动作可以自然成立，不能按“每秒必须有变化”的配额编造小动作。

逐镜表、节拍、标题总时长、英文Shot时间与JSON一致。标题是整秒范围，按自然内容选相近段长；实际17n+5帧网格输出可能略有偏差，接力上下文偏移另按一致性指南核对。对白或动作过早结束时缩短或合并，不能为凑片长让模型重演。

## 收到反馈

记清具体段/时点、用户实际现象、提交文本和参数；成片未提供可按提示词定位缺口，但原因仍按证据区分。用户确认画面出现与台词一致的文字可登记为对白文字化现象，不能把 `<d>` 格式视为已排除字幕。

保留已认可的台词、音色、素材、镜头与种子，只改命中项；文件检查与成片验证分开。状态采用“待实测 / 文件层已验证 / 用户复测通过 / 复测失败”，不把经验写成保证。报告和临时记录放工作区 `.codex/reports`，不堆进skill。

文本修订只重生本段；接力源改变检查后续依赖链；共用素材或锁改变检查全部引用段。用户只改skill时不擅改现有项目。安装后核对源与安装文件哈希，后续新会话加载新版本。
